# 任务完成同步清单

## 五部分同步铁律

**五个部分必须保持内容一致。任一部分更新后，必须检查其余四部分是否需要同步。**

| # | 部分 | 文件 | 位置 | 内容 |
|---|---|---|---|---|
| 1 | **目标** | Note | `# 目标` | 研究目标、指标编号（目标X.Y）、验证结论 |
| 2 | **实验计划** | Note | `# 流程` | 每个实验的复选框、验收标准、结果摘要 |
| 3 | **实验结论** | Note | `# 结论` | 按指标分组，每个实验一句话结论 |
| 4 | **实验报告** | report | 各实验 H3 块 | 每个实验的完整报告（日期、结论、参数、指标、备注） |
| 5 | **代码架构** | src | `# scripts` / `# lib` / `# tests` / `# main` | 函数清单（复选框）、数据管线、设计决策、各实验数据流与参数溯源 |
| 6 | **项目日程表** | Schedule | 对应日期标题下 | 任务复选框、完成状态 |

**同步触发规则：**
- 跑完实验 → 更新 ①②③④⑤⑥（脚本注释如无需改动可跳过⑤中的函数清单）
- 修正实验逻辑 → 更新 ①②③④⑤⑥
- 修改验收标准 → 更新 ①②④
- 更新实验结论 → 更新 ①③④

---

**每次完成一个实验脚本后，必须同步更新以下所有位置：**

## 同步清单

| # | 文件 | 位置 | 操作 |
|---|---|---|---|
| 1 | **Note** | `# 目标` | 若实验 `目标` 字段以 `验证目标X.Y` 开头，标记对应编号的目标复选框 `[x]` |
| 2 | **Note** | `# 流程` → 对应实验 | 标记实验复选框 `[x]`，更新产出中的关键数值结果 |
| 3 | **Note** | `# 结论` → 对应指标 | 追加/更新一句话结论 |
| 4 | **report** | 对应实验 H3 块 | 追加/更新实验报告（日期、结论、参数、指标、备注）。**参数名用 LaTeX**（`$T_{sim}$` 非 `T_sim`）、科学计数法用 `$1.23 \times 10^{-15}$` |
| 5 | **src** | `# main` → 对应实验 | 标记实验复选框 `[x]`，更新产出说明；若新增 scripts/lib 文件，在对应小节追加条目 |
| 6 | **Schedule** | 对应日期标题下 | 标记实验相关任务复选框 `[x]` |
| 7 | **代码** | 所有新写的 `.m` 文件 | **写→格式化→跑**：运行 `fix_m_code.py <file> --apply` 规范化大小写，AI 审查 diff 修复误改（🔴外部API还原 / 🟡改变量名 / 🟢保留专有名词），确认无误后再在 MATLAB 中跑通 |

## 特别注意

- src `# main` 中每个实验的复选框最容易遗漏——每次完成实验后必须检查。
- Note `# 流程` 中的复选框与 src `# main` 中的复选框是两套独立列表，都需要更新。
- Note `# 结论` 与 report 中的实验报告结论措辞必须一致（结论可更简洁）。
- 若新增了 scripts 或 lib 文件，在 src 对应小节追加条目并标注上下游依赖。

## 运行复盘（自动）

**每次跑通实验后**，复盘运行过程中遇到的操作问题，按分类写入对应位置：

| 问题类型 | 写入位置 | 示例 |
|---------|---------|------|
| 通用（任何项目都可能遇到） | skill 对应文件 | Simulink `sim_w.Data` 属性名例外 → `FORMAT.md` Case conventions |
| 本项目特定 | 项目 `CLAUDE.md` → `## 运行须知` | 本项目的 toolbox 依赖、特殊启动步骤 |

写入原则：
- **精炼**：只写操作步骤，不写原因分析。一行能说清不写两行
- **可复现**：清空环境后按描述操作就能跑通
- **自动执行**：每次跑通实验后 AI 主动复盘，不等用户提醒

```
...
```

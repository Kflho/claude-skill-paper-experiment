# 任务完成同步清单

## 五部分同步铁律

**五个部分必须保持内容一致。任一部分更新后，必须检查其余四部分是否需要同步。**

| # | 部分 | 文件 | 位置 | 内容 |
|---|---|---|---|---|
| 1 | **目标** | Note | `# 目标` | 研究目标、指标编号（目标X.Y）、验证结论 |
| 2 | **实验计划** | Note | `# 流程` | 每个实验的复选框、验收标准、结果摘要 |
| 3 | **实验结论** | Note | `# 结论` | 按指标分组，每个实验一句话结论 |
| 4 | **实验报告** | report | 各实验 H3 块 | 每个实验的完整报告（日期、结论、参数、指标、备注） |
| 5 | **代码架构** | src | `# scripts` / `# lib` / `# tests` / `# main` | 函数清单（复选框）、数据管线、设计决策、各实验数据流（纯参考）与参数溯源 |
| 6 | **项目日程表** | Schedule | 对应日期标题下 | 任务复选框、完成状态 |

**同步触发规则：**
- 跑完实验 → 更新 ①②③④⑤⑥（脚本注释如无需改动可跳过⑤中的函数清单）
- 修正实验逻辑 → 更新 ①②③④⑤⑥
- 修改验收标准 → 更新 ①②④
- 更新实验结论 → 更新 ①③④

> **Schedule 操作边界（铁律）**：对 Schedule（④`# 问题`、⑥ 日期标题下）只允许勾选/取消**已有**复选框 `[x]`，禁止新增/编辑任何文字（日期章节、任务条目、修复备注等）。修复内容简述写入 report 备注（⑤/表格第 5 行），不写入 Schedule。

---

**每次完成实验或修复脚本逻辑后，按以下清单同步更新所有位置：**

## 同步清单

| # | 文件 | 位置 | 操作 | 场景 |
|---|---|---|---|---|
| 1 | **Note** | `# 目标` | 若实验 `目标` 字段以 `验证目标X.Y` 开头，标记对应编号的目标复选框 `[x]` | 常规 + 修复 |
| 2 | **Note** | `# 流程` → 对应实验 | 标记实验复选框 `[x]`，更新方法步骤（公式推导链、参数来源）、判定准则、产出中的关键数值结果。修复场景额外：删除论文不存在的指标，同步图片引用 | 常规 + 修复 |
| 3 | **Note** | `# 结论` → 对应指标 | 追加/更新一句话结论。修复场景若结论改变需同步 | 常规 + 修复 |
| 4 | **Schedule** | `# 问题` | 仅标记已修复问题为 `[x]`（修复内容简述写入 report 备注，不写入 Schedule） | 仅修复 |
| 5 | **report** | 对应实验 H3 块 | 追加/更新实验报告（日期、结论、参数、指标、备注）。参数名用 LaTeX（`$T_{sim}$` 非 `T_sim`）、科学计数法用 `$1.23 \times 10^{-15}$`。修复场景：更新结论（若变）、指标（填入计算值）、备注（说明修复内容和根因） | 常规 + 修复 |
| 6 | **src** | `# main` → 对应实验 | 「各实验数据流」条目为纯参考（**不带复选框**，实验完成状态只在 Note `# 流程` 标记）；完成时更新其数据流/产出描述；新增 scripts/lib 文件则在该小节追加 `- [x]` 条目。修复场景额外：同步数据流描述（特别是理论计算等关键步骤）、参数溯源表 | 常规 + 修复 |
| 7 | **src** | `# 设计决策` | 若修复涉及设计决策（如检测准则、公式推导），更新 Dx 条目 | 仅修复 |
| 8 | **Schedule** | 对应日期标题下 | 标记实验相关任务复选框 `[x]` | 常规 + 修复 |
| 9 | **代码** | 所有新写/修改的 `.m` 文件 | **写→格式化→审查 diff→跑**（工作流与判定基准见 [scripts.md](scripts.md)：按**有罪推定**逐 hunk 判定误改/正确规范，不留未判项；还原过的词进项目词表 `.fix_m_code_protect`），`--check` 退出码 0 后再在 MATLAB 中跑通。修复场景额外：更新头部注释的方法描述、参数溯源引用、验收标准，确保与代码逻辑一致 | 常规 + 修复 |
| 10 | **CLAUDE.md** | — | 若修复揭示了新的运行须知（如特定参数敏感、方法限制），追加到 `## 运行须知` | 仅修复 |
| 11 | **src** | `# lib` / `# scripts` | 函数清单随实验设计同步更新。`[手写]` 函数写清接口规范（签名、输入/输出、公式出处）；`[AI组装]` 函数标注调用了哪些手写函数 | 常规 + 修复 |
| 12 | **图** | `outputs/{cn,eng}/experiment_XX/figures/` + 论文引用处 | **出图后必须看图**：逐张打开确认非空白、曲线/坐标/图例符合预期、标题单行；论文里的图 `pdftocairo -png -r 100 <pdf> <前缀>` 渲染后逐页目视核对。范围 = 本次产出的每一张（中英两套）＋论文引用的每一张。空白或错图 → 回生成脚本改、重跑出图，再看一遍（编译退出码与页数不算核过） | 常规 + 修复 |

**特别注意**：

- src 带复选框的只有 `# scripts`/`# lib`/`# tests` 文件清单（标记已实现）；`# main`「各实验数据流」条目不带复选框——不要为完成的实验在那里打 `[x]`，实验状态只在 Note `# 流程`（含 report/Schedule）维护
- Note `# 结论` 与 report 中的实验报告结论措辞必须一致（结论可更简洁）
- 公式推导链必须可追溯：每次修改变量/参数来源后，确保从论文公式到脚本实现的每一步都有明确出处
- 删除臆造指标时必须同时删除相关图片引用：Note 产出图片列表、src 产出说明、report 中的数据文件描述，三处同步删除
- 论文方法核实优先：修复前先对照论文原文确认方法，避免用一个错误替代另一个错误

## 运行复盘（自动）

**每次跑通实验后**，复盘运行过程中遇到的操作问题，按分类写入对应位置：

| 问题类型 | 写入位置 | 示例 |
|---------|---------|------|
| 通用（任何项目都可能遇到） | skill 对应文件 | Simulink `sim_w.Data` 属性名例外 → `format.md` Case conventions |
| 本项目特定 | 项目 `CLAUDE.md` → `## 运行须知` | 本项目的 toolbox 依赖、特殊启动步骤 |

写入原则：
- **精炼**：只写操作步骤，不写原因分析。一行能说清不写两行
- **可复现**：清空环境后按描述操作就能跑通
- **自动执行**：每次跑通实验后 AI 主动复盘，不等用户提醒

```
### experiment_01_xxx

...
```

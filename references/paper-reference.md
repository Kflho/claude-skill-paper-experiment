# Paper reference

## 目录结构

论文 PDF 和 markdown 的存放位置在初始化时确定（可在项目内，如 `references/`，无需强制外部目录），记录到项目 CLAUDE.md 的 `## Scientific Research Paths` 表中（`论文文件夹` 字段）。

每篇论文在论文文件夹下有自己的子文件夹，以论文标题命名（PDF 文件名去掉 `.pdf`）：

```
<论文文件夹>/
  <Paper Title>/
    <Paper Title>.pdf      # 原始 PDF
    paper_full.md           # 全文 markdown
    paper_p1-5.md           # 前 5 页 markdown（可选）
```

论文文件夹位置在初始化时确定（可在项目内，也可在外部目录）。若在项目内，按需用 `.gitignore` 排除大文件（如 PDF/PPTX）。

## 读取流程

当用户要求参考论文、读取 PDF 或查阅论文中的技术细节：

1. 从项目 CLAUDE.md → `## Scientific Research Paths` → `论文文件夹` 获取路径。
2. 在该路径下按论文标题关键词匹配子文件夹。
3. **子文件夹中有 `.md`** → 直接 Read（优先 `paper_full.md`）。**但 `.md` 只够读方法/流程描述——公式必须回原生 PDF 取，见下节。**
4. **子文件夹不存在或仅有 PDF** → 调用 `pdf-converter` skill 创建文件夹并转为 markdown。

## 公式载体

公式**只存在于原生载体**里，纯文本提取会静默丢掉它们。同一份材料可能有多个版本，读公式时按载体选：

| 载体 | 公式在哪 | 怎么读 |
|---|---|---|
| PDF | 文本层的公式对象 | 走 `pdf-converter`；公式渲染异常/乱码时按页截图核对 |
| pptx / docx | OMML 公式（`m:f` 分式、`m:func` 函数、`m:nary` 求和、`m:sSubSup` 上下标） | 解压后从 `ppt/slides/slideN.xml`（docx 为 `word/document.xml`）抠出 OMML，逐 token 还原 |
| 由以上转出的 `.md` | **没有公式** | 只能用来定位（哪页/哪节有公式）；**不能用来读公式内容** |

**读公式四条：**

1. **纯文本 `.md` 不得作为公式依据。** 这类提取文件开头通常自带声明（如"不含版式/公式图形"）——看见这句话就当公式全丢处理，回到原生载体重新取。
2. **先验证提取方法，再采信结果。** 挑一个能在别处独立核对的公式（如 PPT 某页 vs 论文正文对应节），逐字比对；对得上，才用该方法读其余公式。
3. **看结构树，不靠肉眼读渲染文本。** 括号嵌套、分式范围、求和上下限以 OMML 节点结构为准；用脚本 dump 出结构树逐项比对。
4. **同一份文档里公式可能不同源。** 有的条目是真 OMML，有的是作者手打的纯文本（每个 token 都是裸 `m:r`，没有 `m:nary`/`m:func`）。手打纯文本里的符号（如 `·`）按字面理解，不能当成公式结构来读；发现混用时记录并上报。

## 两类文献文件的区别

- **Obsidian `{项目名} 参考文献.md`**：用户自己的解读笔记，AI 只读不写。
- **`<论文文件夹>/<Paper Title>/paper_full.md`**：原始论文文本，供 AI 在方法论和实验设计阶段查阅。
